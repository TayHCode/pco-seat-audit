# Public API review — 2026-10-13

Only public developer reference pages were read for this review. Account pages were not opened. Paid-limit semantics and pasted-page shapes come from one observation on 2026-10-13; no account-specific billing figures are included here. A separate two-request, authorised real check confirmed the root field shapes, retaining only field names and types privately.

The [API index](https://api.planningcenteronline.com/docs/apps) lists API, Calendar, Check-Ins, Current, Giving, Groups, People, Publishing, Registrations, Services and Webhooks. Each linked product index below was checked for billing/subscription resources, then its organisation resource was inspected:

- [API index, 2026-09-24](https://api.planningcenteronline.com/docs/apps/api/versions/2026-09-24): developer integration/token resources. [Organisation](https://api.planningcenteronline.com/docs/apps/api/versions/2026-09-24/vertices/organization) has an ID and integration/token associations; no subscription or billing fields.
- [Calendar index, 2026-06-22](https://api.planningcenteronline.com/docs/apps/calendar/versions/2026-06-22): event/resource/booking operations. [Organisation](https://api.planningcenteronline.com/docs/apps/calendar/versions/2026-06-22/vertices/organization) has name, date/time preferences and onboarding; no paid tier, rooms package size or subscription price.
- [Check-Ins index, 2025-05-28](https://api.planningcenteronline.com/docs/apps/check-ins/versions/2025-05-28): attendance/events/people. [Organisation](https://api.planningcenteronline.com/docs/apps/check-ins/versions/2025-05-28/vertices/organization) has identity, timestamps, date/time preferences and integer `daily_check_ins`. Its paid-limit interpretation is supplied by the observation; the reference itself gives no definition. Implemented as `GET /check-ins/v2/`. It does not give tier names, paid status or price.
- [Current index, 2018-08-01](https://api.planningcenteronline.com/docs/apps/current/versions/2018-08-01): current organisation/person. [Organisation](https://api.planningcenteronline.com/docs/apps/current/versions/2018-08-01/vertices/organization) has name, subdomain, time zone and a people association; no billing or subscribed-products association.
- [Giving index, 2019-10-18](https://api.planningcenteronline.com/docs/apps/giving/versions/2019-10-18): donations, funds, donor/payment operations. [Organisation](https://api.planningcenteronline.com/docs/apps/giving/versions/2019-10-18/vertices/organization) has name, time zone, and `text2give_enabled`; no subscription price or paid donation limit. Enabled donation features do not establish what is paid.
- [Groups index, 2023-07-10](https://api.planningcenteronline.com/docs/apps/groups/versions/2023-07-10): groups, membership and attendance operations. [Organisation](https://api.planningcenteronline.com/docs/apps/groups/versions/2023-07-10/vertices/organization) has name/time zone and operational associations; no paid group-member limit or billing.
- [People index, 2026-10-05](https://api.planningcenteronline.com/docs/apps/people/versions/2026-10-05): people, app access, workflows, etc. [Organisation](https://api.planningcenteronline.com/docs/apps/people/versions/2026-10-05/vertices/organization) has identity, country, grades, date/time preferences and operational associations (including apps/stats); no subscription billing fields.
- [Publishing index, 2024-03-25](https://api.planningcenteronline.com/docs/apps/publishing/versions/2024-03-25): content and episode resources. [Organisation](https://api.planningcenteronline.com/docs/apps/publishing/versions/2024-03-25/vertices/organization) has name, subdomain and opt-in `downloads_used`; this is usage, not an allowance, subscription tier or price.
- [Registrations index, 2025-05-01](https://api.planningcenteronline.com/docs/apps/registrations/versions/2025-05-01): signup/attendee operations. [Organisation](https://api.planningcenteronline.com/docs/apps/registrations/versions/2025-05-01/vertices/organization) has name and timestamps; no paid attendee limit or subscription billing.
- [Services index, 2018-11-01](https://api.planningcenteronline.com/docs/apps/services/versions/2018-11-01): service planning operations. [Organisation](https://api.planningcenteronline.com/docs/apps/services/versions/2018-11-01/vertices/organization) has `people_allowed`, `people_remaining`, storage fields and add-on flags. Implemented `GET /services/v2/` reads the two people fields and `file_storage_size`/`file_storage_size_used`, deriving occupied seats. The reference lists the storage-size fields as boolean; the real check returned integers, so the reader validates integer values without inventing units. `file_storage_extra_charges` is documented as integer without units; flags and that field do not establish a complete subscription price or tier. No such price or tier is retrieved.
- [Webhooks index, 2022-10-20](https://api.planningcenteronline.com/docs/apps/webhooks/versions/2022-10-20): notification infrastructure. [Organisation](https://api.planningcenteronline.com/docs/apps/webhooks/versions/2022-10-20/vertices/organization) has only ID and webhook associations; no billing.

Cross-product/account candidates checked:

- [People App](https://api.planningcenteronline.com/docs/apps/people/versions/2026-10-05/vertices/app) defines offered apps and exposes name/URL. It does not document active paid subscription status, tier, limit or price. Returning an app is not evidence of payment.
- [PersonApp](https://api.planningcenteronline.com/docs/apps/people/versions/2026-10-05/vertices/person_app) describes person/app access, login permission and people permissions, not organisational subscriptions.
- [OrganisationStatistics](https://api.planningcenteronline.com/docs/apps/people/versions/2026-10-05/vertices/organization_statistics) documents an ID-only example and a statistics collection, with no paid plan fields.
- [ConnectedApplication](https://api.planningcenteronline.com/docs/apps/api/versions/2026-09-24/vertices/connected_application) exposes integration description/name/URL and associated people, not a product subscription.
- [OauthApplication](https://api.planningcenteronline.com/docs/apps/api/versions/2026-09-24/vertices/oauth_application) exposes developer applications, not account billing.
- [OauthApplicationMau](https://api.planningcenteronline.com/docs/apps/api/versions/2026-09-24/vertices/oauth_application_mau) counts token-issued monthly users for a developer application, not paid product seats.
- [WebhookSubscription](https://api.planningcenteronline.com/docs/apps/webhooks/versions/2022-10-20/vertices/webhook_subscription) has notification active/application/delivery configuration, not a billing subscription.
- [Getting Started](https://api.planningcenteronline.com/docs/overview/getting-started) documents API access on free tiers, so access itself cannot establish payment. The bare `/docs/overview` URL was inaccessible through the documentation reader; its Guides link resolved to this page.
- [Add-ons overview](https://api.planningcenteronline.com/docs/overview/add-ons) and [Add-ons API reference](https://api.planningcenteronline.com/docs/overview/add-ons/api-reference) describe UI extensions and authenticated fetch helpers; they offer no additional billing endpoint.
- [Authentication](https://api.planningcenteronline.com/docs/overview/authentication) documents the Personal Access Token id/secret pair with HTTP Basic, the developer-account creation/revocation route and user-dependent permissions. The client uses only its GET path, with a User-Agent identifying the local tool.

No complete subscription/billing catalog endpoint was found in these references. The implementation uses the documented partial roots, administrator-pasted Subscriptions/Change plans text, and explicit manual corrections. It never guesses endpoints or changes plans. Authorised private checks verified saved page structures; synthetic fixtures reproduce their quirks with invented values. The general default ladder remains a dated reference.

Live Giving and Check-Ins responses advertise `created_at` in `meta.can_query_by`. Authorised GET checks confirmed `where[created_at][gte]` and `where[created_at][lte]` restrict both returned records and `meta.total_count` to the requested window, including an empty future window. Giving uses that filtered total for record metrics. Check-Ins pages filtered records for distinct-person metrics; a collection total cannot establish that count. Registrations does not advertise a date query and Publishing does not advertise its publication date query, so those collections are paged and dated locally. Only same-host, same-collection next links are followed, with a quarter-second request spacing and a 100-page bound. Incomplete counts never support downgrade or saving advice. All examples and tests remain synthetic. No real responses or account figures are included here.
